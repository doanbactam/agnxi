# AIStack

> The shortest path to the right AI coding stack.

AIStack helps developers choose an agent, model, MCP server, and skill set without researching dozens of disconnected sources.

## Product promise

Pick a goal. See the smallest stack that works. Copy the setup. Ship.

```text
Goal → Agent → Model → Tools → Skills → Working setup
```

## User

A developer who already uses—or is choosing—an AI coding agent and wants a reliable setup for a specific job.

They do not need another news feed, benchmark archive, or exhaustive marketplace. They need a decision.

## Core jobs

1. **Discover** what fits the job.
2. **Compare** only meaningful differences.
3. **Compose** compatible parts.
4. **Install** with copy-ready commands.
5. **Return** when the stack or ecosystem changes.

## Information model

- **Agent** — who executes.
- **Model** — what powers it.
- **MCP** — what it can access.
- **Skill** — how it should work.
- **Stack** — the recommended combination for one outcome.

Every item must answer five questions:

1. What is it for?
2. Who is it for?
3. What works with it?
4. How do I install it?
5. Why choose it over the nearest alternative?

If the content cannot answer these, it is not ready to publish.

## Primary experience

### 1. Start with intent

The first screen asks what the developer wants to accomplish. Product categories are secondary.

Examples: maintain a large codebase, prototype a UI, review a pull request, automate browser work.

### 2. Show a recommendation

Return one primary stack and a small number of alternatives. Explain the trade-off in one sentence.

### 3. Reveal the mechanism

Use a simple system diagram to show how the selected agent, model, MCPs, and skills connect. The diagram is functional, not decorative.

### 4. Make setup immediate

Keep install commands, required keys, compatibility, and verification steps beside the recommendation. Copy is a primary action.

### 5. Keep depth optional

Default to the answer. Put benchmarks, long explanations, and full metadata behind deliberate drill-down.

## Content rules

- Lead with the decision, not the background.
- One sentence per claim.
- One idea per section.
- Use verbs for actions and nouns for categories.
- Prefer specific trade-offs over ratings.
- Never repeat the same fact in a badge, paragraph, and table.
- Remove text that does not improve choice, trust, or setup.
- Mark freshness, source, and uncertainty when they affect a recommendation.

## Trust

A recommendation must be:

- **Compatible** — verified against the named agent and current setup method.
- **Current** — dated and reviewed when upstream behavior changes.
- **Explainable** — includes a short reason.
- **Reproducible** — includes setup and verification.
- **Independent** — sponsorship never changes ranking without disclosure.

## Scope

### Now

- Browse agents, models, MCP servers, and skills.
- Search by name, task, and capability.
- View compatibility and copy setup commands.
- Follow an agent-specific setup path.
- See a small set of recommended stacks.

### Next

- Intent-first stack finder.
- Side-by-side trade-off comparison.
- Saved stacks and setup progress.
- Automated freshness and compatibility checks.
- Community corrections with source evidence.

### Not now

- Social feed or engagement mechanics.
- Generic AI news.
- A complete registry of everything.
- Rankings without a defined use case.
- Decorative personalization.

## Success

The product succeeds when a developer reaches a credible setup faster and with fewer open tabs.

Primary signals:

- Time from entry to copied setup command.
- Recommendation-to-install conversion.
- Successful setup verification.
- Return rate after ecosystem updates.
- Correction rate for stale or incompatible guidance.

## Product principles

1. **Decision before directory.** A smaller useful answer beats a larger catalog.
2. **Show how it works.** Diagrams clarify relationships that prose hides.
3. **Less, but sufficient.** Remove everything except choice, reason, and action.
4. **Progressive depth.** A novice gets a path; an expert can inspect the evidence.
5. **Write the reason.** If a product or design decision has no clear reason, cut it.
6. **Respect attention.** No ornamental sections, fake urgency, or engagement traps.

## North star

**Less browsing. Better decisions. Faster builds.**
